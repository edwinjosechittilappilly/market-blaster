# Existing skills and publishing tools

Survey date: 2026-11-21. Scope: published documentation and repository metadata, not a hands-on security, quality, or delivery audit. Dates below are latest default-branch commit dates observed in GitHub commit feeds, not proof of active support. SaaS is proprietary unless stated otherwise; hosted-service source license and last deploy are generally [UNVERIFIED]. Provider coverage is what the cited source claims, not a guarantee that a particular account can publish today.

## Summary: decisions

- Build the distinctive part: a reusable agent skill that turns a PR, commit range, README, or changelog into evidence-linked, developer-relevant narratives and platform-specific drafts. Existing release-note and social skills solve pieces; [Pipepost](https://github.com/MendleM/Pipepost) and [content-distribution-mcp](https://github.com/AutomateLab-tech/content-distribution-mcp) are close competitors, so validate differentiation against them rather than claiming novelty.
- Reuse existing guidance on audience, voice, launch framing and threads; do not equate social marketing templates with accurate release evidence. [Marketing Skills](https://github.com/coreyhaines31/marketingskills), [release-notes-writer](https://www.skills.sh/jayrha/agent-skills/release-notes-writer), [LinkedIn-to-X](https://www.skills.sh/liftli-ai/linkedin-agent-skills/linkedin-to-x).
- Keep drafting and publishing separable. [Crosspost](https://github.com/humanwhocodes/crosspost) already offers a permissive CLI, library and MCP; investigate its per-platform strategies before implementing overlapping protocol plumbing.
- Make a reviewable per-platform draft, explicit publish confirmation and per-destination results first-class. [Typefully's plugin](https://github.com/typefully/typefully-plugin) already distinguishes draft, schedule and destructive operations; [content-distribution-mcp](https://github.com/AutomateLab-tech/content-distribution-mcp) documents per-channel idempotency.
- Treat article syndication as its own workflow: canonical URLs, images, stable remote IDs and updates matter. [DEV CLI](https://github.com/sinedied/devto-cli), [Hashnode action](https://github.com/Hashnode/publish-github-action), and [Pipepost](https://github.com/MendleM/Pipepost) show useful patterns.
- Offer schedulers as optional backends, not a mandatory paid account: [Postiz](https://github.com/gitroomhq/postiz-app) offers self-hosting; [Buffer](https://buffer.com/pricing) has free-tier API access; [Ayrshare](https://www.ayrshare.com/pricing) is substantially more expensive for a solo developer.
- Respect provider constraints rather than promising universal automation: [Hashnode's action](https://github.com/Hashnode/publish-github-action) says API publishing requires Pro; [Typefully](https://support.typefully.com/en/articles/8718287-typefully-api) limits public multi-user X use; the [distribution MCP](https://github.com/AutomateLab-tech/content-distribution-mcp) returns browser handoffs for some destinations.
- Design for local credential handling, scoped authority and review; avoid handing a model raw credentials or placing API keys in URLs. Postiz offers bearer/OAuth options and Typefully offers OAuth for its MCP. [Postiz auth](https://docs.postiz.com/mcp/introduction), [Typefully plugin](https://github.com/typefully/typefully-plugin).

## Gap analysis

The competitive space is materially crowded. [content-distribution-mcp](https://github.com/AutomateLab-tech/content-distribution-mcp) already accepts per-channel variants, applies channel hints and tracks idempotency; [Pipepost](https://github.com/MendleM/Pipepost) already generates network-specific social content from articles and cross-publishes with canonicals. [Typefully](https://github.com/typefully/agent-skills) and [Postiz](https://github.com/gitroomhq/postiz-app) already provide agent-facing publishing. **[INFERENCE]** The underserved seam observed in this survey is the combination of source-code change evidence, trustworthy developer-specific storytelling, editable per-platform variants, and a portable CLI independent of any one scheduler—not an absence of social AI tools. This is a bounded observation, not proof nobody else implements it.

1. **Evidence and precision:** map each claim, example, limitation and migration note to source PR/commit/docs; avoid inventing metrics, capabilities, benchmarks or shipped status. Distinguish what changed from why it matters. Release-note guidance is a starting point, not verification. [Release skill](https://www.skills.sh/jayrha/agent-skills/release-notes-writer).
2. **Developer-native outcomes:** explain problem, technical tradeoff, before/after usage and links to repository or docs, then shape each result for the destination and community. Avoid generic identical promotional spam. Existing network-specific rewriting is demonstrated by [LinkedIn-to-X](https://www.skills.sh/liftli-ai/linkedin-agent-skills/linkedin-to-x); the opportunity is linking that process to real shipped evidence.
3. **Local review and safe execution:** portable files for variants, validation, explicit user authorization, deterministic dry-run, per-platform success/failure and duplicate prevention. Account for ambiguous network outcomes rather than falsely claiming exactly-once publishing. [Distribution MCP](https://github.com/AutomateLab-tech/content-distribution-mcp), [DEV CLI](https://github.com/sinedied/devto-cli).
4. **Article lifecycle and platform gaps:** store canonical source, remote IDs, revision and account/destination state; update rather than blindly re-create when the platform supports it. Unsupported or restricted destinations should be explicit handoffs, not fake successes. [Hashnode action](https://github.com/Hashnode/publish-github-action), [distribution MCP](https://github.com/AutomateLab-tech/content-distribution-mcp).

## Build versus reuse

| Capability | Decision | Rationale / evidence |
|---|---|---|
| PR/commit/README/changelog to evidence-backed developer story | **Build** skill and portable draft contract | No surveyed tool documented this exact end-to-end evidence trace; adapt [release skill](https://www.skills.sh/jayrha/agent-skills/release-notes-writer) and [marketing skills](https://github.com/coreyhaines31/marketingskills), retaining attribution/license where required. |
| Platform style, voice and thread structure | **Reuse/adapt** skill guidance | [LinkedIn-to-X](https://www.skills.sh/liftli-ai/linkedin-agent-skills/linkedin-to-x) and [social skill](https://github.com/coreyhaines31/marketingskills/blob/main/skills/social/SKILL.md) already address voice and formatting; verify changing constraints against platform docs. |
| Social API transport | **Evaluate reuse first** | [Crosspost](https://github.com/humanwhocodes/crosspost) offers strategies, CLI, distinct text and MCP under Apache-2.0. Add a native adapter only for documented missing semantics or platforms. |
| Scheduling and account management | **Integrate optionally** | [Postiz](https://docs.postiz.com/mcp/introduction), [Typefully](https://support.typefully.com/en/articles/8718287-typefully-api), [Buffer](https://developers.buffer.com/guides/getting-started) already provide scheduling; don't rebuild a dashboard or scheduler by default. |
| Article cross-post and lifecycle | **Reuse where appropriate; build missing contract** | [Pipepost](https://github.com/MendleM/Pipepost) and [DEV CLI](https://github.com/sinedied/devto-cli) cover article distribution; persist IDs, canonical URLs, draft status and outcomes in our own portable representation. |
| Review, state and publishing safety | **Build product-specific orchestration; borrow patterns** | [Distribution MCP](https://github.com/AutomateLab-tech/content-distribution-mcp) and [LinkedIn MCP](https://github.com/2060-io/linkedin-mcp) demonstrate idempotency and safety budgets; require explicit confirmation and honest uncertain/partial outcomes. |
| Medium, HN, Reddit and restricted APIs | **Capability-gated adapter or explicit handoff** | Do not promise automation without access; [distribution MCP](https://github.com/AutomateLab-tech/content-distribution-mcp) already models browser-required channels and Reddit as gated. |
