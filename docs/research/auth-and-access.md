# Publishing authentication, access and reach

Research snapshot: 2026-11-21. Scope is one developer publishing their own reviewed announcement, not bulk posting or scraping. **[UNVERIFIED]** means the primary sources examined did not establish the detail, not that it is unavailable. Prices are USD list prices, before taxes, and can change. No route guarantees immunity from moderation or bans. Review content and community rules immediately before each publish. A logged-in browser is not itself permission to automate it; opening a page and having the human paste and click is different from scripting that page.

## Decisions first

- Use existing official APIs for DEV, Bluesky, Mastodon and GitHub; Hashnode is worth enabling if a Pro publication is already useful. Preserve originals and canonical links for substantive articles, not promotional link stubs. Use LinkedIn's self-serve personal publishing permission where granted, but default to manual LinkedIn if setup/reauthorization is more trouble than the benefit; company publishing is separately restricted.
- For X choose an already-connected scheduler or paid official API only if its incremental reach justifies the cost. Prefer manual human posting on HN, Reddit, Lobsters, Product Hunt, Medium and Substack; do not automate logged-in pages to get around API access restrictions. Threads offers an official write API but setup/review makes an established scheduler or manual composer more practical for a solo developer.
- Add GitHub Releases/Discussions for project users, Discord webhooks and an opt-in newsletter for retained audience, not as claims of mass discovery. Add Lobsters as a manual, community-dependent handoff; treat daily.dev as a source/discovery distribution opportunity, not a verified posting API. Telegram is optional where the developer already has a channel. [JUDGEMENT]
- An official MCP server is an interface, not extra platform permission or an exemption from rates, costs, policy or review. Managed schedulers trade credential/approval maintenance for an additional vendor, cost, account connections and the vendor's coverage restrictions. The same explicit human approval should gate any MCP/API publish.
- Reach tiers below are **[JUDGEMENT]**, not measured impressions: 1 = highest potential discovery among relevant developers/entrepreneurs, 2 = meaningful niche/network, 3 = mostly existing audience, specialized or uncertain. Actual performance varies enormously with account, post and community. A high tier is not a license to cross-post promotional spam.

Free and paid plans exist; exact price and API entitlement by plan are **[UNVERIFIED]**. [Buffer](https://developers.buffer.com/guides/getting-started) has GraphQL and [prices](https://buffer.com/pricing): free three channels, 10 queued per channel, 1,000 API requests/channel/month up to 3,000; Essentials $6/channel/month monthly. Its pricing lists X, LinkedIn, Bluesky, Mastodon and Threads; API feature parity **[UNVERIFIED]**. [Postiz](https://postiz.com/pricing) hosted Standard is $29/month for five channels including API/MCP; [self-hosted](https://github.com/gitroomhq/postiz-app) avoids that subscription but needs infrastructure and provider app setup. [Ayrshare](https://www.ayrshare.com/pricing) Premium is $149/month; its [network list](https://www.ayrshare.com/docs/apis/post/social-networks/overview) includes X, LinkedIn, Reddit and Bluesky. [Hypefury](https://hypefury.com/mcp) lists $6/month/platform or $19/month for six and an OAuth MCP for LinkedIn, Threads, Bluesky and Instagram; availability, X support via MCP, and API parity **[UNVERIFIED]**. Scheduler pricing is per account/plan, not a promise that every network or feature is included; verify current checkout and terms.

Unless explicitly identified below, an official platform MCP/SDK, a relevant scheduler integration, exact token expiry, refresh, separate approval and wait, and API cost are **[UNVERIFIED]**. A manually logged-in account requires no API token or OAuth scopes; its session expires per the provider. Wait time is never assumed to be zero merely because no review is documented. SDKs are client libraries, not alternative access rights. Community MCPs named below are third-party code, not platform-endorsed and require credential/security review.

## Platform details

### DEV / Forem

- **Setup/access:** create a DEV account, open settings → Extensions/API keys, generate a key, supply it as `api-key` to `POST /api/articles`; no granular scopes are documented here. Select `published: false` for review and specify `canonical_url` when syndicating. Key expiry, refresh, approval wait and current API price **[UNVERIFIED]**. [Forem API](https://developers.forem.com/api/v1). [Community DEV MCP](https://github.com/Arindam200/devto-mcp) and [Crosspost](https://github.com/humanwhocodes/crosspost) wrap API access, not an official MCP.
- **Rules:** [DEV terms §11](https://dev.to/terms) require “substantial content” and prohibit posts designed primarily for promotion/backlinks. This is a content restriction, not a verified blanket browser-automation prohibition; official API publishing is documented. Browser automation rules **[UNVERIFIED]**. [JUDGEMENT] Technical walkthroughs and tags are a good developer-discovery fit; a bare feature link is not.

### Hashnode

- **Setup/access:** create account and publication, buy [Pro](https://hashnode.com/pro) at $5/seat/month, create a personal access token and find publication ID; GraphQL `publishPost` or drafts use the token. API reading and publishing require Pro; PAT lifetime, refresh, granular scopes and review/wait **[UNVERIFIED]**. [Policy change](https://hashnode.com/changelog/2026-05-13-graphql-api-paid-access), [official action](https://github.com/Hashnode/publish-github-action), [mutation reference](https://github.com/Hashnode/gql-skill/blob/main/skills/gql-api/references/mutations.md). Alternatively the [official MCP](https://hashnode.com/blog/hashnode-mcp-server) at `https://mcp.hashnode.com/mcp` uses browser login and consent, no PAT, and can publish, draft, edit and delete; it also requires Pro. Revoke connected clients in Developer Settings; MCP grant lifetime **[UNVERIFIED]**.
- **Rules/reach:** [Terms §6](https://hashnode.com/terms) prohibit “automated content generation for the purpose of manipulating search results or engagement metrics” and automated access exceeding reasonable use; §7 requires review of AI suggestions in its editor. This is not a blanket ban on the documented publishing API. The API terms enumerate permitted use and restrictions; if the intended commercial publishing use is unclear, seek clarification rather than infer a guarantee. [JUDGEMENT] Developer blogs and canonical syndication are relevant; discovery is not guaranteed.

### GitHub: Gists, Discussions and Releases

- **Setup/access:** sign into GitHub and run `gh auth login` or create a least-privilege token. Gists use `gist` for classic tokens or fine-grained Gists write permission, `POST /gists`; secret gists are unlisted rather than private drafts. [Gists API](https://docs.github.com/en/rest/gists/gists), [visibility](https://docs.github.com/en/get-started/writing-on-github/editing-and-sharing-content-with-gists/creating-gists). For Releases enable repository access, use fine-grained **Contents: write**, `POST /repos/{owner}/{repo}/releases`; for Discussions enable Discussions on the repository and use GraphQL `createDiscussion` with repository and category IDs and **Discussions: write**. Classic PATs require appropriate repository scopes; org SSO restrictions may apply. [Releases](https://docs.github.com/en/rest/releases/releases), [GraphQL mutations](https://docs.github.com/en/graphql/reference/mutations#creatediscussion), [Discussions setup](https://docs.github.com/en/discussions/quickstart). Set expiry when creating PAT; rotate/reissue on expiration, no PAT refresh flow established. No separate app review for a personal PAT is documented; org approval may apply; actual wait **[UNVERIFIED]**. GitHub Free exists; paid plan/organization restrictions vary. [PAT guidance](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens).
- **Options:** GitHub's [official MCP server](https://github.com/github/github-mcp-server) supports GitHub operations; verify exact tool and write permissions for each destination, especially Gists and Discussions, before depending on it. REST/GraphQL and `gh` are documented alternatives. [Community distribution MCP](https://github.com/AutomateLab-tech/content-distribution-mcp) advertises Discussions.
- **Rules/reach:** [Acceptable use](https://docs.github.com/en/site-policy/acceptable-use-policies/github-acceptable-use-policies) prohibits “automated excessive bulk activity and coordinated inauthentic activity”, including spam; this does not prohibit normal release APIs. Releases and Discussions reach repository watchers/users, while Gists are linkable artifacts, not equivalent to discovery feeds. [JUDGEMENT] Release notes help existing users most.

### LinkedIn — personal profile and company page

- **Personal:** create a LinkedIn developer app, associate/verify a Page if prompted, add self-serve **Share on LinkedIn**, OAuth authorize `w_member_social`, then post on the member's behalf. Access tokens generally last 60 days; programmatic refresh is program-dependent, so plan to reauthorize. Product/app access, user consent and token permissions are separate; self-serve is not the same as blanket Marketing API approval. Actual approval/wait and cost **[UNVERIFIED]**. [Share](https://learn.microsoft.com/en-us/linkedin/consumer/integrations/self-serve/share-on-linkedin), [auth](https://learn.microsoft.com/en-us/linkedin/shared/authentication/getting-access), [refresh](https://learn.microsoft.com/en-us/linkedin/shared/authentication/programmatic-refresh-tokens).
- **Company:** the member must administer the page; request the relevant LinkedIn Marketing/Community Management API access, OAuth `w_organization_social` and required supporting permissions, then create a post with the organization URN. Product tier, partner review, exact administrator roles and approval wait depend on the granted program; do not assume personal `w_member_social` covers a company. [Posts API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/posts-api), [permissions](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/organization-access-control-by-role).
- **Options:** official REST, [Typefully](https://github.com/typefully/agent-skills), [Buffer](https://buffer.com/pricing), [Postiz](https://github.com/gitroomhq/postiz-app), [Ayrshare](https://www.ayrshare.com/docs/apis/post/social-networks/overview), [Hypefury](https://hypefury.com/mcp); verify each for profile versus company and API plan. [Community MCP](https://github.com/2060-io/linkedin-mcp); official publishing MCP **[UNVERIFIED]**. Manual [share-offsite](https://www.linkedin.com/sharing/share-offsite/) shares a URL, not arbitrary prefilled text.
- **Rules/reach:** [User agreement §8.2](https://www.linkedin.com/legal/user-agreement) prohibits software, scripts, robots and similar tools used to “scrape the Services or otherwise copy profiles and other data”; it also restricts unauthorized automation. Human approval does not convert prohibited browser scripts into permitted access. Official authorized API and manual clicking are different paths. [JUDGEMENT] Personal network and company followers are relevant to B2B/entrepreneur reach; their sizes and ranking outcomes are account-specific.

### X

- **Setup/access:** create a developer account/project/app, configure user-context OAuth 2.0 (`tweet.write`, `tweet.read`, `users.read`, plus `offline.access` for a refresh token) or OAuth 1.0a user credentials, authorize own account and call `POST /2/tweets`. Token lifespan/rotation depends on flow; use returned expiry and refresh token, or reauthorize. Developer review/wait **[UNVERIFIED]**. The [official pay-per-use pricing](https://docs.x.com/x-api/getting-started/pricing) lists $0.015/create and $0.20/create with URL; verify current console prices and any credits before connecting. [Post API](https://docs.x.com/x-api/posts/create-post).
- **Options/rules:** [official xmcp](https://github.com/xdevplatform/xmcp) and [hosted X MCP](https://docs.x.com/tools/mcp) wrap X API and its credentials/pricing. The hosted server uses OAuth authorization code with PKCE; `offline.access` enables refresh and app-only bearer is read-only. Scheduler choices and caveats above apply. [Automation rules](https://help.x.com/en/rules-and-policies/x-automation) prohibit “non-API-based forms of automation, such as scripting the X website” and warn of permanent suspension; they allow informational automated posts subject to anti-spam rules. Human approval does not create an exception to the scripting prohibition. [JUDGEMENT] Strong founder/developer networks may make this tier 1; follower and link distribution are not guaranteed.

### Bluesky

- **Setup/access:** create an account, generate a distinct app password under settings, authenticate against the account's PDS using `com.atproto.server.createSession`, and create `app.bsky.feed.post` with `com.atproto.repo.createRecord`. App password scope is its account delegation, not OAuth granular scopes; expiry **[UNVERIFIED]**, revoke/recreate if exposed. Session JWTs expire; refresh or reauthenticate. For a multi-user application prefer [AT Protocol OAuth](https://atproto.com/guides/oauth). API approval wait and paid requirement for ordinary account posting **[UNVERIFIED]**. [Post guide](https://bsky.network/docs/bluesky-api/creating-a-post). Official SDK [@atproto/api](https://github.com/bluesky-social/atproto); [community MCP](https://github.com/Ravishka17/Bluesky-MCP); official publishing MCP **[UNVERIFIED]**. Typefully, Buffer and Postiz list Bluesky.
- **Rules/reach:** [community guidelines](https://bsky.social/about/support/community-guidelines) say “Do not send spam or repeatedly post content in ways that disrupt normal conversations or service use.” This is not a blanket ban on documented API posting; browser automation rule **[UNVERIFIED]**. Custom feeds/followers enable discovery, but reach is not guaranteed. [JUDGEMENT] Good developer niche at low integration friction.

### Mastodon

- **Setup/access:** choose the home server, register an application via settings or `POST /api/v1/apps`, then authorize a user token with `write:statuses`, plus `write:media` for uploads; call `POST /api/v1/statuses` on that server. Token expiry/refresh are server/version dependent and **[UNVERIFIED]**; protect/revoke credentials. Instance signup, approval, cost and rules vary; no universal review wait. [API guide](https://docs.joinmastodon.org/client/intro), [statuses](https://docs.joinmastodon.org/methods/statuses/), [scopes](https://docs.joinmastodon.org/api/oauth-scopes/). Typefully, Buffer and Postiz list Mastodon; official MCP **[UNVERIFIED]**.
- **Rules/reach:** instance rules are authoritative for that instance; inspect the server's `/about` and policies, including bot-account labeling and promotion. [Mastodon documentation](https://docs.joinmastodon.org/methods/instance/) exposes server rules. No universal ToS quote or uniform browser-automation permission exists across independently run servers; **[UNVERIFIED]** until the actual instance is chosen. [JUDGEMENT] Federated hashtag/follower communities are useful but reach varies by instance and audience.

### Threads

- **Setup/access:** create a Meta developer app with Threads use case, connect the Threads account, authorize `threads_basic` and `threads_content_publish`; create a media/text container and then publish it. Short-lived tokens last one hour; exchange for a 60-day token, refresh after at least 24 hours and before expiry. Grants last 90 days; refresh extends grants for public, not private, profiles, so private-profile users must re-consent. Production use by non-testers requires Advanced Access; review/verification and wait depend on access level. Price **[UNVERIFIED]**. [Publishing](https://developers.facebook.com/documentation/threads/create-posts), [token lifecycle](https://developers.facebook.com/documentation/threads/get-started/long-lived-tokens/). Typefully, Buffer, Postiz and Hypefury list Threads, subject to feature parity.
- **Rules/reach:** Meta's [automated data collection terms](https://www.facebook.com/legal/terms/datacollection) and [Threads terms](https://help.instagram.com/769983657850450) must be checked for the actual use: data scraping clauses are not automatically proof that human-approved API publishing is forbidden. Exact browser-posting clause **[UNVERIFIED]**. [JUDGEMENT] Broad social discovery, but developer targeting is less assured than DEV/HN.

### Reddit

- **Setup/access:** apply for developer access, register an app and obtain user OAuth `submit` scope; use `POST /api/submit` for a self or link post only after approval. Cost, granted quota, token lifetime/refresh and review time depend on access and are **[UNVERIFIED]**; do not assume registering an app itself grants current Data API access. [Responsible Builder Policy](https://support.reddithelp.com/hc/en-us/articles/42728983564564-Reddit-Data-API-Terms), [API](https://www.reddit.com/dev/api/#POST_api_submit). Postiz/Ayrshare list Reddit; check current subreddit, product and API eligibility.
- **Rules/reach:** [Reddit terms](https://redditinc.com/policies/user-agreement) and API policy apply; app approval and community moderator rules are independent. Browser automation prohibition for own reviewed post **[UNVERIFIED]**; use manual submission rather than assume approval. [JUDGEMENT] Relevant subreddits can have high impact but prohibit or restrict promotional links. Read live rules of [r/programming](https://www.reddit.com/r/programming/about/rules/), [r/SideProject](https://www.reddit.com/r/SideProject/about/rules/), and [r/webdev](https://www.reddit.com/r/webdev/about/rules/) before posting; exact self-promotion ratios, allowed days and Showoff Saturday applicability are **[UNVERIFIED]**, and can change.

### Hacker News

- **Setup/access:** create an HN account; no paid API token, OAuth scope or refresh for manual use. Its [official API](https://github.com/HackerNews/API) documents reads, not submissions. Open the [submit form](https://news.ycombinator.com/submit) or prefilled `submitlink?u=...&t=...`; user logs in and clicks submit. Account approval/wait and posting limits **[UNVERIFIED]**. No verified official write MCP.
- **Rules/reach:** [HN guidelines](https://news.ycombinator.com/newsguidelines.html) say “please don't automate posting”, “Please don't put generated text in HN posts”, and not to use HN primarily for promotion or solicit upvotes. The user must write and submit their own post, not just approve a generated draft or automated submit. [Show HN](https://news.ycombinator.com/showhn.html) is for something people can try; do not submit every minor release. [JUDGEMENT] Front-page discovery can be exceptional for substantive technical launches, but is rare and volatile.

### Lobsters

- **Setup/access:** Lobsters is an invite-based computing community; obtain an account through a member invite, then manually submit on site. No OAuth scope/token for this workflow, no API publishing access or review wait established. Cost and official write MCP **[UNVERIFIED]**. [Site](https://lobste.rs/), [about](https://lobste.rs/about).
- **Rules/reach:** [Guidelines](https://lobste.rs/about) say “New users ... are not allowed to submit self-promo”; as a rule of thumb, self-promotion must be less than a quarter of stories and comments in the last year. During the first 70 days new users also cannot use `show` or `announce` tags. Spam flags include commercial promotion and content without meaningful human authorship. Browser-automation prohibition **[UNVERIFIED]**; use manual only. [JUDGEMENT] Small computing-focused audience, high relevance, but entrepreneurship itself is off-topic and community acceptance matters.

### Medium

- **Setup/access:** sign in and use manual import/editor. [Medium](https://help.medium.com/hc/en-us/articles/213480228-API-Importing) no longer issues new integration tokens or allows new integrations; previously authorized integrations may use the [legacy API](https://github.com/Medium/medium-api-docs), including `canonicalUrl`. New-user token lifetime/refresh, waiting time and API cost are inapplicable to a manual workflow; account/subscription eligibility for particular features **[UNVERIFIED]**. No verified new official write MCP.

This restriction applies to the API and should not be treated as consent to generated content merely because a human approved it. Exact browser automation clause **[UNVERIFIED]**. [JUDGEMENT] Import substantive long-form content for broader reading and possible discovery; reach depends on publications and distribution.

### Substack

- **Setup/access:** create publication and use its editor to publish manually. Official [MCP](https://support.substack.com/hc/en-us/articles/50834026608916-How-to-connect-Substack-to-your-AI-Assistant) is read-only, for eligible Bestseller publication admins, and cannot publish. A public supported write API, token lifetime, scopes and API review/cost are **[UNVERIFIED]**. Typefully advertises Substack Notes, not proof of full newsletter publishing; verify account connection/availability. Avoid unofficial cookie endpoints.
- **Rules/reach:** [Terms](https://substack.com/tos) restrict auto-responders, logged-out processes, scraping and crawling; do not use browser scripts or undocumented cookies to bypass the supported workflow. [API terms](https://substack.com/api-tos) impose separate restrictions on permitted data use. The exact applicability to an individually approved browser post **[UNVERIFIED]**. [JUDGEMENT] Subscriber delivery and recommendations can build an audience, but list size and discovery are not guaranteed.

### daily.dev

- **Setup/access:** create an account; use **New post** to write or share a link manually, or create a free Squad. Established developer publications can suggest an RSS source once the suggester has 250 reputation; **company and personal blogs are not eligible as sources**. A paid Verified Company Squad may auto-post its RSS/YouTube; quote and onboarding wait **[UNVERIFIED]**. Claim authorship if a publication already indexed carries your article. Whether any particular DEV/Hashnode post is picked up is **[UNVERIFIED]**. [Getting featured](https://docs.daily.dev/how-to-get-featured/). Official write API/MCP, scopes and token lifetime **[UNVERIFIED]**.
- **Rules/reach:** [Content guidelines](https://docs.daily.dev/content-guidelines/) reject “AI-generated content, automated algorithms” and content primarily for self-promotion, SEO or AI visibility; human approval alone does not erase these limits. Direct sharing of genuinely human-authored, relevant developer material is distinct from permitted paid Squad RSS ingestion. Browser automation clause **[UNVERIFIED]**. [JUDGEMENT] Useful developer discovery, but indexed source inclusion is not guaranteed.

### Discord webhooks

- **Setup/access:** obtain Manage Webhooks permission in a server/channel, create an incoming webhook under channel integrations, copy its secret URL, then `POST` JSON content to it. URL is a bearer secret, not a user OAuth token; expiry/refresh **[UNVERIFIED]**, revoke/delete and recreate if leaked. Server admin permission is required; separate Discord app approval and fee **[UNVERIFIED]**. [Official webhooks](https://docs.discord.com/developers/resources/webhook), [setup](https://support.discord.com/hc/en-us/articles/228383668-Intro-to-Webhooks). [Crosspost](https://github.com/humanwhocodes/crosspost) supports Discord.
- **Rules/reach:** Discord says “Automating normal user accounts ... outside of the OAuth2/bot API is forbidden” and can terminate accounts. [Self-bot policy](https://support.discord.com/hc/en-us/articles/115002192352-Automated-User-Accounts-Self-Bots). A documented incoming webhook is distinct from automating a user account. [JUDGEMENT] High relevance to an existing project server; not a discovery engine, and never post to other servers without permission.

### Telegram channels

- **Setup/access:** use [@BotFather](https://t.me/BotFather) to create a bot and receive its token; add it as an administrator of your channel with permission to post; send `sendMessage` to the channel ID or `@channelusername`. Bot token is a secret; revoke/reissue via BotFather if leaked; expiry/refresh **[UNVERIFIED]**. Telegram documents free bot broadcasts up to its ordinary threshold and paid higher throughput, not an unconditional unlimited free service. Review/wait **[UNVERIFIED]**. [Bot API](https://core.telegram.org/bots/api#sendmessage), [bot setup](https://core.telegram.org/bots/features#botfather), [bot terms](https://telegram.org/tos/bot-developers). [Crosspost](https://github.com/humanwhocodes/crosspost) supports Telegram.
- **Rules/reach:** [Bot terms §5.2](https://telegram.org/tos/bot-developers) say the bot “must not harass or spam users with unsolicited messages”; §4.3 separately restricts scraping and datasets. Owner-approved channel publishing is distinct from scraping or unsolicited DMs; personal-account browser automation rules **[UNVERIFIED]**. [JUDGEMENT] Good opt-in retention if a relevant channel exists, not guaranteed new-audience discovery.

### Buttondown / newsletter APIs

Delete or regenerate the key if exposed; expiry/refresh, account review/wait and free-plan API entitlements **[UNVERIFIED]**. - **Rules/reach:** [acceptable-use policy](https://buttondown.com/legal/acceptable-use-policy) says “We do not allow spam” and requires subscribers to “double opt-in”; it also prohibits prose and images that are primarily machine generated. Human review does not necessarily make primarily machine-generated content compliant. Automated sending through the documented API is distinct from scraping; browser automation clause **[UNVERIFIED]**. [JUDGEMENT] Strong retention and portability of an existing list, little intrinsic initial discovery.
